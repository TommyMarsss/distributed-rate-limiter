# 分布式令牌桶限流器（模拟）

多个节点共享同一个全局配额的令牌桶限流器。**仅使用 Go 标准库**，不依赖任何
第三方分布式协调组件（etcd / Redis 等）；报告为单一静态 HTML 文件，只用原生
HTML/CSS/JavaScript（Canvas 2D），不引入任何前端框架或图形库。

```
coordinator.go   全局令牌桶 + 租约发放/归还/过期回收
node.go          节点：本地配额、定期同步、低水位预取、故障/恢复
sim.go           离散事件模拟器：虚拟时钟、网络延迟、流量发生、状态采样
clock.go         时钟抽象（真实时间 / 固定偏移，模拟时钟不同步）
report.go        汇总模拟结果并生成单文件 HTML 报告
template.go      报告模板（原生 JS + Canvas，无任何依赖）
cmd/ratelimsim/  演示：4 节点 + 时钟偏移 + 突发 + 故障/恢复，输出 report.html
sim_test.go      自动化测试（超额边界 / 故障回收 / 时钟公平性 / 流量场景）
```

## 运行

```bash
go test ./...                    # 运行全部测试
go run ./cmd/ratelimsim          # 运行模拟，生成 report.html
open report.html                 # 浏览器查看曲线与事件高亮
```

## 一、配额协调协议（租约制）

集中式令牌桶的吞吐受单点限制，纯本地限流又无法保证全局配额。这里采用
**租约（lease）** 折中：协调器持有唯一的全局令牌桶（容量 `C`，匀速补充速率
`r`），节点不逐请求询问协调器，而是**批量领取**令牌到本地消费：

1. 每个节点每隔 `SyncInterval` 向协调器申请一个租约（一批 `B` 个令牌）；
   协调器在**授予时**即从全局桶扣除，桶空则少发或不发——
   协调器是限流决策的唯一权威。
2. 节点在本地放行请求，每个请求消耗 1 个本地令牌。
3. 本地令牌降至低水位（默认 `B/2`）时**提前预取**下一批，避免同步往返
   期间令牌耗尽造成毛刺拒绝；新租约到达前继续消耗旧租约，不存在令牌真空期。
4. 新租约到达时，旧租约的剩余令牌立即归还全局池（即使剩余为 0 也要回报，
   见下文「回收的正确性」）。
5. 所有消息都经过模拟的网络延迟（`LinkLatency`）。

## 二、节点故障与配额回收

租约带有 TTL（`LeaseTTL`）。节点故障后不再消费、不再归还，其持有的租约
成为「僵尸配额」；协调器每隔 `ReclaimPeriod` 扫描一次，把**已过期的未归还
租约**的令牌重新计入全局池：

- 故障节点的配额最迟在 `故障时刻 + TTL + ReclaimPeriod` 内回到全局池，
  不会永久占用（对应测试 `TestLeaseReclaimAfterNodeFailure`）。
- 故障是**有界**的配额损失：任一时刻每个故障节点最多锁住 `B` 个令牌。
- 节点恢复后重新申请租约即可，无需特殊处理（对应测试 `TestNodeRecovery`）。

**回收的正确性**：租约过期时协调器无法知道节点已消耗多少，按租约全额回收
可能把已消费的令牌重复计入。协议用两点把该误差约束在理论边界内：

1. 活跃节点每次换发租约时**总是**回报旧租约剩余量（包括 0），因此活跃节点
   的租约在一个同步周期内即被正常关闭，不会走到 TTL 回收；
2. 只有故障节点的租约会走到 TTL 回收，其「已消费但被全额回收」的误差
   每次故障不超过 `B` 个令牌——这正是超额边界中 `N·B` 项的来源之一。

## 三、时钟偏移的处理

各节点本地时钟与协调器可能存在固定偏移。协议**不在租约有效性判定中使用
任何绝对时间戳**：

- 协调器只发送相对时长 `TTL`；
- 节点收到租约时记录 `leaseValidUntil = 本地当前时间 + TTL - SafetyMargin`，
  用本地时钟的**相对时长**判定租约是否有效。

设租约在真实时刻 `g` 授予，响应经单向延迟 `L` 到达节点，节点时钟偏移为
`δ`（节点时钟 = 真实时间 + δ）。节点停止使用租约的真实时刻为

```
t_stop = (g + L + δ) + TTL - M - δ = g + TTL + L - M      （M = SafetyMargin）
```

**偏移 `δ` 被完全消去**：只要 `M > L`（安全余量大于单向网络延迟），节点
必然在协调器回收租约（`g + TTL`）之前停止使用它，与时钟偏移无关。
因此时钟偏移不会让任何节点获得不成比例的放行优势——各节点的令牌供给
只取决于同步周期与批大小（对应测试 `TestFairnessUnderClockSkew`，
±400ms 偏移下各节点放行数 max/min ≈ 1.14）。

## 四、超额边界的理论推导

设 `A(t)` 为到时刻 `t` 全部节点累计放行的请求数。与理想集中式令牌桶
（同期最多放行 `C + r·t`）比较：

**令牌守恒**：全局桶的令牌只有三个去向——被租约带出（在途）、被消费
（放行）、留在桶内；补充速率恒为 `r`，初始为 `C`。因此

```
已消费令牌 ≤ C + r·t - 桶内 - 在途 ≤ C + r·t
```

唯一可能突破该上界的是**重复计入**：协调器按租约全额做 TTL 回收，而租约
中部分令牌可能已被节点消费（僵尸消费）。设 `Z(t)` 为被重复计入的令牌
总量，则

```
A(t) ≤ C + r·t + Z(t)
```

**推论 1（正常运行，Z = 0）**：当 `SafetyMargin > 单向网络延迟` 时，活跃
节点总在租约过期前停止使用并归还它（见第三节），TTL 回收只作用于故障
节点；若故障节点下线前未消费（题目设定），回收是精确的，故

```
A(t) ≤ C + r·t
```

**推论 2（一般情形，Z ≤ N·B）**：每个节点任一时刻至多持有一个租约
（≤ B 个令牌），因此「已消费却可能被全额回收」的在途租约总量不超过
`N·B`（N 为节点数）。即使计时假设被破坏，也有保守工程边界

```
A(t) ≤ C + r·t + N·B
```

直观含义：超额只来自「在途未结算」的租约，是有界的一次性毛刺（量级为
全部节点各一批令牌），不会随时间累积放大。测试
`TestOvershootWithinTheoreticalBound` 与 `TestMultiNodeBurst` 在
需求远超配额的负载下验证该边界成立（例如 4 节点、B=10、15s 内
放行 837 ≤ 100 + 50×15 + 40 = 890）。

## 六、HTML 报告

`go run ./cmd/ratelimsim` 生成单一静态文件 `report.html`（数据与绘图逻辑
全部内嵌，离线可开），包含：

- 全局池可用令牌与被租约占用令牌随时间的曲线（含容量上限参考线）；
- 各节点本地令牌曲线；
- 各节点累计放行曲线，叠加理论上限 `C + r·t + N·B` 参考线；
- 节点故障（红）、配额回收（黄）、节点恢复（绿）事件的竖线高亮与时间线列表。
